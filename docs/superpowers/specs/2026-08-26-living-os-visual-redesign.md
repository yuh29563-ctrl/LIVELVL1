# LIVELVL Living OS 全局视觉与动效重构设计规格

日期：2026-08-26
状态：待用户书面审阅
实施分支：`codex/rewards-mvp`
基线：`cde355c`

## 1. 目标

把 LIVELVL 从现有手帐、手写字、像素装饰和通用 SwiftUI 卡片堆叠，重构为一套统一的“Living OS”产品界面：高级、克制、未来 iOS、银灰黑白、动效优先，同时保留并强化任务、成长、收藏和现实奖励之间的产品闭环。

用户要求尽可能 1:1 复刻已确认的最终预览。这里的“1:1”定义为：

- 页面信息层级、主要比例、留白、材质、颜色、字体气质和交互状态与预览一致。
- 动效遵循预览表达的空间关系，并在真实 SwiftUI 中跟手、可中断、可恢复。
- 内容使用真实领域数据，不硬编码预览中的示例数字和示例卡片。
- 在 iPhone 17 Pro 上作为主参考尺寸，同时适配 Dynamic Type、安全区和其他 iPhone 宽度。
- 不把预览 PNG 当成界面背景，也不以不可交互的图片冒充实现。

发生冲突时，优先级固定为：

1. 已确认的产品规则和领域不变量。
2. 可访问性、Reduce Motion、数据完整性与真实设备安全区。
3. 本规格中的交互与布局规则。
4. 最终参考图的视觉比例。
5. 参考图中的示例文字、示例数值和生成式细节。

参考图中的 `身体 / 专注 / 秩序 / 连接 / 成长 / 恢复` 是概念占位。正式实现必须映射现有六个领域：`健康 / 学习 / 事业 / 财务 / 关系 / 兴趣`，不修改 `LifeDimension` 的业务语义。

## 3. 不可破坏的产品边界

- 现实奖励兑换继续完全本地运行，不增加网络、账户、云同步、支付或商城后台。
- 金币仍使用整数 `coinUnit`：`1 XP = 1 coinUnit`，`10 coinUnit = 1.0 金币`。
- `CoinTransaction`、`RewardProduct`、`RewardRedemption` 及现有原子兑换规则不改变。
- 现实奖励领域不得写入或复用 `CardRewardService`。
- `PendingCardReward`、`OwnedCollectible`、`CollectionProgress` 和收集奖励队列的语义不改变。
- 伙伴成熟卡、隐藏发现卡一旦获得不会因 XP 撤销而追回。
- 卡片飞向“收集”Tab 的领取流程、队列顺序和真实 UIKit 目标坐标必须保留。
- 不通过删除测试、放宽断言或改变规则制造通过结果。
- 不推送远端、不合并分支，除非用户明确要求。
- 不暂存、覆盖或提交主工作区中的 `project.pbxproj`、`UserInterfaceState.xcuserstate` 和 `.tmp/`。

## 4. 产品叙事

Living OS 的核心闭环为：

```text
完成现实任务
  → 对应生命维度响应
  → XP 与 coinUnit 同步记账
  → XP 粒子汇入生命核心
  → 等级与核心形态成长
  → 成熟或隐藏卡片出现
  → 卡片飞入 Archive
  → 金币可兑换用户定义的现实奖励
```

六维生命场表达“此刻的状态”；生命核心组件表达“长期成长中的我”；Archive 表达“永久拥有的成长证据”；Rewards 表达“成长对现实生活的回报”；You 表达“跨时间观察自己的系统”。日记不是主成长载体，本阶段不新增日记模块。

## 5. 全局视觉系统

### 5.1 色彩

建立新的语义化视觉令牌，替代页面内散落颜色：

| 令牌 | 推荐初值 | 用途 |
| --- | --- | --- |
| `canvas` | `#F4F5F6` | 页面主背景 |
| `surface` | `#F8F9FA` | 生命组件和收藏卡表面 |
| `ink` | `#0B0C0D` | 主标题、主数据、选中节点 |
| `graphite` | `#666A70` | 次要文字、不可兑换状态 |
| `mist` | `#D9DCE1` | 点阵、轨迹、进度底轨 |
| `hairline` | 黑色 10% | 分隔线和卡片边界 |
| `signal` | `#FF3B30` | 极少量事件信号 |

约束：

- 移除持续使用的蒂芙尼蓝、绿色奖励色、暖色纸张和手帐纹理。
- `signal` 只用于新卡、当前事件、兑换动作或 XP 到达点；同屏常态不超过三个小红点。
- 不使用霓虹、彩色渐变、赛博朋克光晕或大面积半透明玻璃。
- 深色模式不在本次 1:1 范围内；若系统切换深色，第一版保持可读的浅色品牌画布，不生成未经设计确认的反色界面。

### 5.2 字体

- 品牌页标题使用 SF Pro / 系统无衬线的黑体气质，主标题为 `Today / Archive / Rewards / You`。
- 删除界面中的手写字体与手帐排版引用；字体文件可暂时保留，避免无意义工程文件变更，但不再被新界面使用。
- 主数据使用等宽数字特征，保证 XP、金币和状态变化时宽度稳定。
- 中文说明使用系统字体，不伪造英文装饰文字。
- 固定尺寸标题和数据必须由 `@ScaledMetric` 或等价策略缩放；辅助功能字号允许换行或调整布局，不允许截断主要操作。

推荐参考尺寸（iPhone 17 Pro 标准动态字体）：

- 页面标题：52–58 pt，Black。
- 大额余额：60–68 pt，Regular/Light，等宽数字。
- 页面核心数据：22–30 pt。
- 正文：16–18 pt。
- 元数据：12–14 pt。

### 5.3 形状与材质

- Today 生命核心组件和 Archive 卡片使用 `RoundedRectangle(style: .continuous)`。
- 核心组件圆角目标 26 pt，Archive 主卡 26–28 pt；最终按真实屏幕截图微调。
- 表面是银白实体材质：极轻内高光、1 px 内外边界、低对比漫反射阴影。
- 禁止普通页面反复堆叠白色圆角卡片。只有“成长物”与“收藏物”拥有实体组件材质。
- 奖励列表、任务列表和设置列表使用排版、留白与发丝分隔线，不使用容器卡片。

### 5.4 点阵语言

- 点阵代表状态、能量、时间和事件路径，不是背景装饰。
- 点阵统一由可测试的布局模型产生，由 SwiftUI `Canvas` 绘制；禁止为每个粒子创建独立 View。
- 点大小、密度、透明度和轨迹受同一组令牌约束。
- 静止状态保持低对比；只有当前交互附近出现局部密度变化。

## 6. App Shell 与底部 Tab

- 四个 Tab 保持：`今天 / 收集 / 奖励 / 我的`。
- 视觉上使用预览中的黑灰线性符号、选中黑色和未选中灰色。
- 必须保留系统 `TabView` / `UITabBar` 作为真实交互与几何坐标所有者，不能用无语义的假底栏替换。
- `CollectionTabFeedbackBridge` 继续解析真实 `UITabBar` 和稳定槽位；只允许调整视觉反馈，不改变目标解析语义。
- 未查看提示使用一个小 `signal` 圆点，不使用持续抖动或高饱和徽章。
- Tab 选择和卡片到达触觉各只触发一次，避免叠加。

## 7. Today

### 7.1 信息层级

从上到下：

1. 大标题 `Today`，右侧仅保留必要的等级或日期元数据。
2. 六维生命场。
3. 中央生命核心组件。
4. 当前 XP、下一等级/形态信息，位于组件内部。
5. 今日任务轨道。
6. 系统 Tab。

### 7.2 六维生命场

- 六个黑色节点按照稳定顺序环绕核心：健康、学习、事业、财务、关系、兴趣。
- 状态显示采用 0–100 展示值：现有 0–10 分数乘以 10 后四舍五入；底层 `LifeStateValues` 不改变。
- 官方状态与行动预估继续来自 `LifeStateSummary`，但不再显示传统雷达图卡片。
- 默认节点显示名称与当前展示值。
- 点击节点后，仅当前节点增加细发丝圆环和一个微小 `signal` 点，附近点阵局部收束。
- 低姿态详情条显示：维度名称、当前值、本周变化、最近来源任务和自评提示；详情从场内自然展开，不使用普通弹窗。
- 再次点击同一节点或点击空白处关闭详情。

### 7.3 生命核心组件

- 中央组件在 iPhone 17 Pro 上约占屏幕宽度 34%，高度约 255–270 pt；小屏按可用宽度缩放。
- 使用 26 pt 连续圆角、银白实体表面、发丝边界和克制阴影。
- 正面内容为当前 `CollectibleDefinition` 与 `CompanionStage` 对应的黑白像素/点阵生命体。
- 像素艺术由静态图鉴资源或可替换的代码/资产定义提供，不在运行时调用 AI，不在本阶段开发像素画编辑器。
- 用户自行设计的正式黑白像素卡素材后续可替换资源，不改变视图和领域模型。
- 组件底部固定显示等级、当前级 XP、进度轨道和“下一形态/下一等级所需 XP”。
- 点击组件进入成长详情；主页面不显示旧手帐照片按钮。现有用户媒体数据不得删除，个性化入口降级到成长详情中的次级操作，避免破坏主视觉。

### 7.4 成长反馈

任务成功完成后的视觉序列：

1. 任务行完成，出现 `+XP` 和一个 `signal` 到达点。
2. 对应六维节点短暂加深，粒子沿可中断轨迹流向核心组件。
3. XP 进度轨道连续增长。
4. 若升级，核心像素密度与轮廓进行一次 600–900 ms 的形态演化，等级文本稳定过渡。
5. 若产生成熟/隐藏卡，等待现有反馈序列结束，再进入原有全局奖励队列。

该序列只改变呈现，不改写任务、XP、金币或卡片奖励的提交顺序。失败或回滚时不播放成功汇入。

### 7.5 任务轨道

- 使用全宽文字行和发丝分隔线，不使用独立圆角卡片。
- 左侧为完成状态，中央为任务名称/必要元数据，右侧显示瞬时 XP 或进入箭头。
- 创建、完成确认、撤销、错误和重试能力保留。
- 空状态使用排版与点阵提示，不使用大号系统插图。

## 8. Archive / 收集

### 8.1 信息层级

1. 大标题 `Archive`。
2. `已收集数量 / 图鉴总数`。
3. 右上角低调的筛选/图鉴入口。
4. 中央横向景深卡组。
5. 当前卡片元数据。
6. 系统 Tab。

图鉴与未发现轮廓继续存在，但从主页面网格移到次级图鉴入口；Archive 主页面只承担已拥有卡片的沉浸式浏览。

### 8.2 卡片内容

- 卡片必须是真正的矩形收藏卡，不使用抽象线框标本代替卡片。
- UI 外壳保持银灰未来 iOS；黑白像素语言只存在于卡片作品内部。
- 卡片正面显示用户/设计者提供的正式黑白像素素材。
- 卡片元数据来自真实 `OwnedCollectible` 与 `CollectibleDefinition`：名称、类型、等级/阶段、获得时间和原因。
- 新卡使用一个小 `signal` 点表示未查看，不靠颜色填满卡片。

### 8.3 横向切换

- 使用原生横向 `ScrollView + LazyHStack` 和稳定 `awardKey`。
- 中央卡片宽度约为可用屏幕宽度 52–58%，两侧卡片必须露出以建立方向感。
- 拖动时当前卡完全跟手；旋转限制在 2–3°，位移、缩放和透明度由卡片距屏幕中心的归一化距离连续计算。
- 下一张由约 88% 缩放到 100%，并逐渐从低对比变为清晰。
- 松手后按系统预测终点吸附到最近卡片；第一张和最后一张有边界，不做无限循环。
- 吸附完成后更新 `centeredAwardKey`，只触发一次选择触觉。
- 只有真正吸附到中央、且 Collection Tab 可见且未被奖励覆盖的卡片才标记为已查看；两侧露出的卡片不算已查看。

### 8.4 展开

- `centeredAwardKey` 与 `expandedAwardKey` 分离，滑动不会误触发展开。
- 点击中央卡片后，使用稳定 ID 和 matched geometry 连续展开。
- 展开时卡片圆角与像素作品保持连续，不出现黑色模态遮罩，也不从无关位置弹入。
- 详细元数据从卡片底部自然展开；翻面能力保留，但 Reduce Motion 下改为交叉淡化。
- 关闭后回到同一中央卡片和滚动位置，VoiceOver 焦点返回该卡片。

### 8.5 新卡落入

- 用户在全局奖励层点击“收下”后，现有卡片仍先按真实模拟器坐标飞向 Collection Tab 中心。
- 到达反馈完成后才完成原有覆盖层关闭语义。
- 新卡持久化和队列完成逻辑不变。
- 用户随后进入 Archive 时，卡组自动定位到对应 `awardKey`，新卡沿短距离点阵轨迹落入卡组并吸附到中央。
- “飞向 Tab”与“落入卡组”是两个独立呈现阶段；后者不得重复领取、重复持久化或消费奖励队列。
- 同一新卡落入动画最多播放一次，使用呈现状态幂等控制；重启后仍必须优先保证卡片存在，而不是强制补播动画。

## 9. Rewards / 现实奖励

### 9.1 原则

- 奖励由用户自行创建，页面不提供或依赖预设商品图标目录。
- 页面不是商城，不显示购物车、商品网格、库存或营销图。
- 用户图片是可选内容；没有图片时保持纯文字，不生成虚构商品图标。

### 9.2 页面结构

1. 大标题 `Rewards`。
2. 顶部 `历史` 与 `+`。
3. 大额可用金币和水平点阵账本。
4. `待兑现` 数量。
5. 用户奖励文字轨道。
6. 系统 Tab。

余额继续从不可变 `CoinTransaction` 聚合，不增加可直接修改的余额字段。点阵只是余额的视觉映射，不参与计算。

### 9.3 奖励轨道

- 每条显示名称、价格、备注和状态，以发丝线分隔。
- 无图片时不保留图标占位；有图片时在条目次级区域显示用户图片。
- 编辑器中显示 `添加图片/替换图片`，而不是要求选择系统图标。
- 当前可兑换条目使用更深文字和低姿态 `兑换` 控件。
- 余额不足条目整体降低对比并明确显示“余额不足”，但仍可进入编辑或查看详情。
- 编辑、归档继续通过条目菜单/详情操作完成；有历史的商品仍不硬删除。

### 9.4 兑换反馈

- 点击兑换先显示包含名称、价格和兑换后余额的原生确认界面。
- 提交期间使用稳定 request key 并禁用重复提交。
- 成功后少量点阵从余额轨道流向对应奖励条目，余额数字同步过渡，记录进入“待兑现”。
- 余额不足、保存失败或重复点击不播放扣币成功动画。
- Reduce Motion 下只更新数字、状态和 `signal` 点，不播放空间粒子。

## 10. You / 我的

### 10.1 原则

- 页面表达“个人运行状态”，不是账户头像页，也不是圆角设置卡片堆。
- App 无账户模型，因此正式标题使用 `You`，身份行使用 `YOU / LEVEL n`，不硬编码参考图中的 `FY`。

### 10.2 页面结构

1. 品牌小字 `LIVELVL` 与 `YOU / LEVEL n`。
2. 大标题 `You`。
3. 综合状态与六维摘要。
4. 本周时间轴。
5. `每周评估 / 数据与隐私 / 设置` 发丝列表。
6. 系统 Tab。

六维摘要与 Today 使用同一 `LifeStateSummary` 数据和同一展示值映射，但 You 是跨时间汇总，不重复 Today 的节点点击详情。

### 10.3 时间轴与设置

- 本周时间轴由完成记录和状态快照派生，不新增网络或分析服务。
- 当前日期使用一个小 `signal` 标记；无活动日期仍保留安静的点阵占位。
- `每周评估` 进入现有评估流程。
- `数据与隐私` 说明所有数据本地保存。
- `设置` 承载次级个性化和辅助功能相关入口。
- Debug 重置入口继续仅在 Debug 可见，并保持两次确认、完整清理和失败报告语义；不直接出现在主视觉第一屏。

## 11. 动效系统

### 11.1 原则

- 动效必须由真实状态变化驱动，可中断、可重建，不依赖固定视频。
- 所有动画从少量统一时长和弹簧令牌中选择，禁止每个 View 随意定义。
- 粒子由 `Canvas` 绘制，时间由 `TimelineView` 或明确的可取消任务驱动。
- 视图离屏、App 非 active 或动画完成后停止时间线，避免持续耗电。
- 不让粒子动画决定领域提交时机；领域结果先可靠保存，呈现层再消费成功状态。

推荐时序：

| 类型 | 目标 |
| --- | --- |
| 按压反馈 | 100–140 ms |
| 节点聚焦 | 220–300 ms |
| 卡片吸附 | 280–380 ms |
| 卡片展开 | 360–480 ms |
| XP 汇入 | 500–700 ms |
| 生命形态升级 | 600–900 ms |

### 11.2 Reduce Motion

- 关闭卡片倾斜、视差、飞行、翻转和粒子路径。
- 保留必要的吸附、淡入淡出、数字更新、静态边界与状态文字。
- 收集奖励继续采用当前已定义的淡出和颜色反馈替代路径。
- 功能结果、焦点顺序、持久化结果和错误处理必须完全相同。

## 12. 技术结构

视觉层按职责拆分，避免把整页写成巨型 View：

```text
DesignSystem/
  LivingOSTheme            色彩、间距、圆角、阴影、字体
  LivingOSMotion           时长、弹簧、Reduce Motion 解析
  DotFieldRenderer         可复用 Canvas 点阵渲染
  LivingSurface            核心组件/收藏卡实体材质

Today/
  TodayLivingOSView        页面编排
  LifeFieldView            六维节点与聚焦状态
  LifeCoreWidget           圆角成长组件
  XPFlowOverlay            任务到核心的呈现粒子
  TaskRailView             任务文字轨道

Collection/
  ArchiveView              页面编排
  ArchiveCarouselState     中央卡、展开卡、新卡落入状态
  ArchiveCarouselView      横向吸附与景深
  ArchiveCardView          黑白像素收藏卡
  ArchiveExpandedView      连续展开与正反面

Rewards/
  RewardStoreView          保留领域查询和用例调用
  RewardBalanceField       余额与点阵账本
  RewardProductRail        纯文字奖励条目
  RewardRedemptionFlow     防重复呈现状态

Profile/
  YouView                  个人状态页面
  WeeklyStateTimeline      本周事件和状态快照
```

文件名可在实施计划中根据现有项目惯例调整，但边界不变：

- 领域模型与服务不依赖视觉组件。
- 页面只调用既有领域用例，不复制金币、XP、成熟、隐藏发现算法。
- 动画状态使用值类型 reducer/状态结构，便于 TDD。
- 共享视觉令牌不持有业务状态。

最低系统为 iOS 17。横向卡组优先使用 iOS 17 原生滚动定位与吸附能力；跨层展开使用同层级 matched geometry，避免依赖只在更高系统可用的 API。

## 13. 性能

- 点阵和轨迹在 `Canvas` 内批量绘制；禁止每个点一个 View。
- 只渲染当前、相邻和必要的卡片内容，卡组使用稳定 ID 和 Lazy 容器。
- 像素艺术路径/采样结果按定义 ID 与形态缓存，不在每帧重新解析。
- 动画更新只观察局部状态，避免余额、任务或查询变化导致整页 Canvas 重建。
- 第一阶段以代码审计和真实设备帧感验收为主；出现掉帧时再使用 ETTrace 定位，不凭感觉优化。

## 14. 可访问性

- VoiceOver 节点读出：维度名称、当前状态、行动预估变化和最近来源。
- 生命核心读出：当前伙伴/核心名称、形态、等级、当前 XP、升级所需 XP。
- Archive 卡片读出：第几张/共几张、名称、类型、新卡状态、获得原因；提供上一个/下一个可访问性调整操作。
- 展开详情关闭后，焦点返回原中央卡片。
- Rewards 读出名称、价格、余额是否足够、备注、归档状态和兑换状态。
- 颜色不是唯一状态渠道，所有红点都对应文字或可访问性值。
- 触控目标至少 44×44 pt。
- Dynamic Type 到 Accessibility 2 仍可完成所有操作；更大字号可改为纵向滚动详情，不压缩主要按钮。

## 15. 错误与边界状态

- 没有状态快照：继续走现有首次评估流程，不展示伪造六维数据。
- 没有任务：显示安静的创建提示并保留添加入口。
- 没有收藏：显示当前幼体生命组件和“第一张卡正在成长”，保留图鉴入口。
- 图鉴定义缺失：跳过无效卡，不崩溃，保留诊断能力。
- 没有现实奖励：显示纯文字创建提示，不出现预设商品或图标。
- 没有奖励图片：条目保持纯文字，不渲染空白缩略图；编辑器显示添加图片入口。
- 余额查询失败：显示不可兑换错误状态，不把失败当作 0 后继续兑换。
- 动画中进入后台：取消呈现任务；回到前台以持久化事实重建，不重复扣币或领取。
- 卡组数据在滑动中变化：按稳定 `awardKey` 协调中央选择；选中卡被移除时选择最近有效卡。

## 16. TDD 与实施顺序原则

正式实施计划必须把每项行为拆为红—绿—重构循环：

1. 先为布局数学、展示映射、动画状态机、卡组选择和幂等呈现写失败测试。
2. 确认测试因缺少目标行为而失败，而不是测试环境错误。
3. 写最小实现使聚焦测试通过。
4. 构建并在 iPhone 17 Pro 安装检查真实布局和坐标。
5. 发现问题先定位根因，再新增回归测试并修复。
6. 每个阶段运行聚焦测试和完整 Debug 测试。
7. 使用小而清晰的提交；不把全局主题、领域改动和四页 UI 混在一个提交。

高层施工顺序固定为：

1. 全局视觉令牌与 App Shell。
2. Today 六维场、生命核心和任务反馈。
3. Archive 卡组、展开和新卡落入。
4. Rewards 纯文字轨道与金币反馈。
5. You 状态系统与时间轴。
6. 跨页动效、无障碍、性能与完整回归。

具体文件、测试名和提交拆分由后续 implementation plan 定义。

## 17. 验收标准

### 17.1 视觉

- iPhone 17 Pro 标准字号下，四个主页面的信息层级、主要比例、银灰黑白材质和留白与最终参考图一致。
- Today 的生命核心明确采用 iOS 小组件式连续圆角，不再出现手帐风、手写字或直角卡片。
- Archive 明确显示黑白像素收藏卡，不能退化为抽象标本或普通网格。
- Rewards 不显示任何预设商品图标；无用户图片时保持纯文字。
- 全 App 不再持续使用蒂芙尼蓝，不出现像素游戏外壳或商城外壳。

### 17.2 交互与动效

- 六维节点可点击并显示真实维度状态。
- 完成任务后对应节点响应，XP 流入生命核心，进度与等级结果正确。
- Archive 可以跟手滑动到上一张/下一张，正确吸附、触觉一次、边界不循环。
- 点击中央卡片连续展开，关闭后位置和焦点正确。
- 新卡领取仍准确飞向真实 Collection Tab 中心；随后进入 Archive 能看到新卡落入卡组。
- Rewards 成功兑换只播放一次金币反馈；余额不足和重复点击不重复扣币。
- Reduce Motion 下所有业务结果一致，且没有必要的空间飞行、倾斜和翻转。

### 17.3 回归与数据

- 现有任务、XP、六维、自评、伙伴成长、隐藏发现和奖励队列测试继续通过。
- 金币余额永不为负，收入与兑换保持幂等，兑换快照不被商品编辑改变。
- Archive 滑动和标记已查看不会提前清除两侧未查看卡片。
- 重启后当前卡、余额、商品、兑换历史和待兑现状态一致。
- Debug 重置清除所有既有业务数据、金币、商品、兑换历史和 `RewardProductImages`。
- Release 不显示 Debug 重置入口。

### 17.4 验证证据

- 完整 Debug 测试零失败，并记录测试数量。
- Release 构建成功。
- iPhone 17 Pro 真实模拟器完成创建任务、任务完成、撤销、升级、六维节点、收藏滑动、卡片展开、奖励创建/编辑/归档、余额不足、成功兑换、重复点击、重启恢复、图片替换和 Debug 重置。
- 保存 Today、Archive、Rewards、You 以及 Archive 四种动效状态的模拟器截图。
- 使用真实坐标重新验收奖励卡飞向 Collection Tab 的起点、终点和到达反馈。
- 检查 Dynamic Type、VoiceOver 和 Reduce Motion。

## 18. 明确不做

- 不新增日记模块。
- 不开发运行时 AI 生图或像素画编辑器。
- 不开发账户、社交、云同步、支付、网络商品或商城后台。
