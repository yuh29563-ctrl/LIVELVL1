# LIVELVL 玻璃悬浮卡与本地媒体背景设计规格

## 目标

将“今天”页的当前陪伴/等级卡与六维状态卡，从贴近页面边缘的普通白色卡片，调整为具有悬浮感的 Liquid Glass 风格组件；同时允许用户为当前陪伴卡选择一张本地照片或 GIF/APNG 动图作为裁剪背景。

本功能是应用内的组件视觉与本地媒体功能，不是 WidgetKit 主屏幕小组件。

## 范围

包含：

- 当前陪伴/等级卡使用悬浮布局：左右保留页面边距，不贴屏幕边缘。
- 六维状态卡使用相同的悬浮组件语言。
- iOS 26+ 使用 SwiftUI 原生 Liquid Glass API。
- iOS 17–25 提供 `ultraThinMaterial` 视觉 fallback。
- 当前陪伴卡提供选择、替换和移除背景媒体的入口。
- 首版支持静态照片、GIF 和 APNG；媒体使用 `scaledToFill` 裁剪，不强行保持完整画面比例。
- 媒体只影响卡片视觉，不影响陪伴、等级、六维、奖励队列或收集数据。
- 本地数据重置同时删除用户卡片媒体和对应 SwiftData 引用。

不包含：

- WidgetKit 主屏幕/锁屏小组件。
- Live Photo、视频背景、云同步、账户同步或网络图片。
- 新的等级规则、奖励规则或卡片业务逻辑。
- 奖励飞向收集 Tab 的动画调整。

## 视觉设计

### 当前陪伴/等级卡

- 使用约 16pt 的水平页面边距，卡片不再贴住屏幕两侧。
- 圆角约 26–28pt，保留当前卡片内容层级和进度条。
- 无背景媒体时显示现有中性浅色背景。
- 有背景媒体时，图片位于卡片底层，使用 `scaledToFill`，再按卡片形状裁剪。
- 图片上叠加可调的对比度遮罩和玻璃层，文字使用能在任意照片上保持可读的颜色。
- 媒体入口使用卡片右上角的小型相机按钮；点击后打开系统照片选择器。
- 提供移除背景动作，移除后恢复中性背景。
- 不在卡片上增加持续高饱和装饰，不改变当前 Tiffany blue 的瞬时反馈语义。

### 六维状态卡

- 使用与当前陪伴卡一致的外边距、圆角、阴影/玻璃形态。
- 雷达图、图例、状态说明和评估入口保持现有结构。
- 首版不为六维卡增加照片背景，避免两张大卡同时竞争视觉焦点。

### Liquid Glass 使用规则

- iOS 26+ 使用 `.glassEffect`；多个相关玻璃表面使用 `GlassEffectContainer` 分组。
- `glassEffect` 放在尺寸、背景媒体和裁剪等布局/外观修饰之后。
- 只有相机按钮等可交互玻璃控件使用 `.interactive()`。
- iOS 17–25 使用 material fallback，保证工程最低部署版本不变。
- 不使用自定义全屏 blur 替代原生 Liquid Glass。

## 媒体选择与渲染

### 选择

- 使用 `PhotosPicker`，只允许选择图片类型。
- 选择后保留原始媒体数据，避免系统重新编码导致 GIF/APNG 变成单帧图片。
- 选择失败或媒体无法解码时，保留原背景并显示可重试错误，不影响页面其他操作。

### 保存

- 图片/GIF/APNG 原始数据保存到 Application Support 下的专用目录，例如 `UserCardMedia`。
- SwiftData 只保存媒体引用：稳定文件名、媒体类型、更新时间和可选像素尺寸。
- 文件名使用 UUID，禁止使用用户原始文件名作为路径，避免冲突和路径问题。
- 写入采用临时文件后原子替换；成功写入后再保存 SwiftData 引用。
- 替换媒体时，先写入新文件，SwiftData 保存成功后再删除旧文件；任一步失败都保留可恢复状态。

### 动图

- GIF/APNG 使用 ImageIO 按原始帧时长解码。
- 在 SwiftUI 中通过小型 UIKit bridge 或等价的本地渲染组件播放帧序列。
- 卡片只播放媒体本身，不叠加额外的缩放、平移或循环动画。
- Reduce Motion 开启时，静态显示首帧，避免背景动图持续运动；照片仍正常显示。
- 对超大 GIF/APNG 设置解码尺寸上限并按卡片显示尺寸缩放，避免一次性占用过多内存。

## 数据与生命周期

新增一个本地媒体引用模型，例如 `UserCardMedia`：

- 稳定 ID。
- 文件名。
- 媒体类型：静态图片、GIF 或 APNG。
- 创建/更新时间。

将模型加入 SwiftData schema，并采用轻量迁移；没有媒体记录时自然回退到默认卡片背景。

`LocalDataResetService` 明确删除：

- `UserCardMedia` SwiftData 记录。
- Application Support 下的 `UserCardMedia` 目录。

删除失败时沿用现有“业务数据已清除但媒体清理失败”的错误呈现，不假报成功。

## 组件与状态边界

- `TodayCompanionLevelCard` 继续接收领域层计算出的等级、经验、陪伴和奖励反馈数据。
- 新增明确的媒体状态输入或环境服务，不在 `body` 中读取文件或执行持久化。
- 媒体选择、保存、删除由独立的本地媒体服务负责。
- `LifeStateCard` 只调整外观容器与间距，不复制媒体逻辑。
- `CardRewardOverlay`、`MainTabView` 和 `CardRewardService` 不改行为。

## 可访问性

- 相机入口标签为“设置陪伴卡背景图片”。
- 移除入口标签为“移除陪伴卡背景图片”。
- 卡片 VoiceOver 仍优先读出陪伴名称、阶段、等级和 XP；背景媒体作为附加状态读出“已设置背景图片/动图”。
- 背景图片不承担任何必须理解的业务信息。
- Reduce Motion 下不播放动图帧动画，仍保留选择、替换和移除功能。

## 验证计划

- 先为媒体引用、媒体类型识别、原子保存/替换、删除失败回滚和 Reduce Motion 首帧策略写单元测试。
- 为玻璃 fallback 和卡片布局提供编译/运行验证，确保 iOS 17 fallback 可构建。
- 在 iPhone 17 Pro / iOS 26.5 上验证：无媒体、有照片、有 GIF/APNG、替换、移除、长文本和深浅照片背景。
- 验证六维卡不贴边、等级卡不贴边，页面滚动和底部 Tab 不被遮挡。
- 运行完整 Debug 测试，并手动确认奖励飞行动画未发生回归。

## 验收标准

- 当前陪伴/等级卡与六维状态卡均以悬浮组件形式显示，不贴屏幕左右边缘。
- iOS 26 上等级卡呈现原生玻璃质感，iOS 17–25 能显示合理 fallback。
- 选择静态图片后，图片填充卡片并按卡片边界裁剪。
- 选择 GIF/APNG 后，卡片可播放；开启 Reduce Motion 时显示静态首帧。
- 替换、移除和 App 重启后媒体状态正确恢复。
- 本地数据重置不会留下用户卡片媒体文件。
- 等级、六维、奖励队列、收集逻辑和奖励飞行动画行为保持不变。
- 完整 Debug 测试通过，真实 iPhone 17 Pro 模拟器手动验收通过。
