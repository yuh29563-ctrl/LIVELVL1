# LIVELVL 收集系统 MVP 设计规格

## 目标与开发边界

本阶段为 LIVELVL 增加以“陪伴养成 + 成熟归档 + 隐藏发现”为核心的收集系统，同时保持现有白色底色、黑灰基础色和克制的养成感。

本阶段包含：

- 底部栏目调整为“今天 / 收集 / 奖励 / 我的”，删除“成长”栏目。
- “今天”顶部增加当前陪伴卡片。
- 普通物种按照等级成长、成熟并归档。
- 隐藏条件达成后，全局自动弹出奖励卡片。
- 收集页、卡片放大与翻转交互、图鉴入口和基础图鉴页。
- 奖励领取队列、未查看状态及收集栏目反馈动画。
- “我的”中增加仅 Debug 可见的本地数据重置入口。
- 使用占位内容提供 3 个普通物种和 2 个隐藏物种，验证完整流程。

本阶段不包含：

- 奖励商城业务逻辑；“奖励”栏目只提供占位页面。
- 完整隐藏任务规则库、正式物种素材和最终卡片文案。
- 奖励商品、金币兑换、相册图片和兑换历史。
- 旧用户收集进度回填。

奖励商城将在收集 MVP 合并后，从最新 `main` 创建独立分支开发；完整图鉴和隐藏规则扩充再放入后续分支。

## 信息架构

底部固定为四个栏目：

1. 今天
2. 收集
3. 奖励
4. 我的

全局奖励展示层位于四栏 `TabView` 之上，因此奖励可以在任意栏目出现，但不会强制改变用户当前所在栏目。

“今天”页面从上到下为：

1. 当前陪伴卡片，作为顶部主视觉，约占手机屏幕高度的六分之一。
2. 等级与经验卡片。
3. 六维状态卡片。
4. 今日任务。

“收集”页面从上到下为：

1. 顶部标题与右上角图鉴入口。
2. 当前正在陪伴的物种或最近获得的重点卡片。
3. 两列成熟卡片网格。

“图鉴”页面采用两列大卡布局：已获得物种显示正式图像，未获得物种只显示灰色植物或动物轮廓。隐藏卡在获得前不展示解锁条件。

## 视觉方向

- 保留白色底色。
- 基础色使用黑色、深灰和浅灰。
- 卡片形态保持简洁、圆角、留白充足，不采用机械或科幻界面。
- 约 30% 的插图和反馈细节可以带有像素感，但不把整套 UI 做成像素游戏。
- 不使用爱心元素，不大量使用星星装饰。
- 蒂芙尼蓝只作为短暂奖励色，用于任务完成、升级、六维变化、卡片领取和收集栏目提示。
- 普通状态下不持续使用高饱和颜色。

## 等级规则

等级计算调整为：

- `0–199 XP = Lv.0`
- `200–2199 XP = Lv.1`
- 从 Lv.1 开始，每增加 `2000 XP` 升一级。

相应进度条规则：

- Lv.0 的当前级经验为 `totalXP`，升级所需经验为 `200`。
- Lv.1 及以上的当前级经验为 `(totalXP - 200) % 2000`，升级所需经验为 `2000`。

当前新建任务由 5–240 分钟和难度 1–5 计算经验，界面可生成的单次最高奖励约为 384 XP。因此 MVP 不把“一次任务跨越多个普通成熟节点”作为正常交互场景，也不为它设计连续成熟动画。领域层仍必须通过唯一奖励键避免重复发放。

## 普通物种养成规则

普通物种按照预设顺序出现，每个普通物种拥有四种素材状态：

1. 幼体
2. 第二形态
3. 第三形态
4. 成熟体

成熟体只在成熟奖励卡与归档卡中展示；成熟卡被收下后，“今天”页面立即换成下一个物种的幼体，因此当前陪伴位不会长时间为空。

首个物种是特殊的新手奖励：

- Lv.0：物种 1 幼体。
- Lv.1：物种 1 直接成熟并等待领取；领取后归档，同时立即出现物种 2 幼体。

之后每三个等级成熟一个物种：

| 等级 | 今天页面当前伙伴 | 同时发生的事情 |
| --- | --- | --- |
| Lv.2 | 物种 2 · 第二形态 | 正常成长 |
| Lv.3 | 物种 2 · 第三形态 | 正常成长 |
| Lv.4 | 物种 3 · 幼体 | 物种 2 成熟、领取并归档后立即补位 |
| Lv.5 | 物种 3 · 第二形态 | 正常成长 |
| Lv.6 | 物种 3 · 第三形态 | 正常成长 |
| Lv.7 | 物种 4 · 幼体 | 物种 3 成熟、领取并归档后立即补位 |

表中的“今天页面当前伙伴”表示该等级的成熟奖励已经收下后的稳定状态。刚达到 Lv.1、Lv.4、Lv.7 等成熟等级但尚未点击“收下”时，旧物种仍是当前伙伴，成熟体由全局奖励卡展示；不能提前把今天页面替换成下一个幼体。

后续按照相同节奏循环。普通物种的排序、四阶段素材和介绍都来自静态图鉴定义，后续可以替换内容而不修改成长算法。

## 撤销任务与永久收集

显示等级继续由当前总 XP 计算，因此撤销任务可以让显示等级降低。收集养成进度单独使用“历史最高等级”，不会因为 XP 撤销而倒退。

- 普通成熟卡一旦触发就永久保留。
- 隐藏卡一旦触发就永久保留。
- 已经切换到下一个物种后，不退回上一个物种的成长形态。
- 相同成熟等级或相同隐藏条件只能发放一次。
- 撤销任务只退回 XP 和对应六维预估，不撤销卡片或历史最高等级。

该规则避免用户在“成熟卡已经归档，但当前伙伴因撤销 XP 退回成长体”的矛盾状态，也避免通过反复完成和撤销任务刷卡。

## 隐藏发现规则

隐藏任务不是用户主动领取的任务，而是系统对完成事件的成就判断，例如：

- 连续 3 天完成学习任务。
- 第一次完成 60 分钟的锻炼任务。

隐藏条件读取带任务快照的完成事件记录，包括完成时间、任务维度、持续时间和任务标识，不依赖当前任务定义是否仍然存在。删除或修改任务不会破坏保留中的历史完成记录；用户主动撤销某次完成时，该次记录不再参与尚未触发的隐藏条件判断。若它已经触发卡片，撤销也不会追回卡片。

MVP 使用数据驱动的规则接口和 2 条占位规则验证流程。后续增加隐藏条件时，应新增规则定义与素材，不修改收集页面结构。

隐藏物种不会成为“今天”页面的当前伙伴，达成条件后直接进入奖励队列，领取后归档到收集栏目。

## 自动弹出与奖励队列

当任务完成或其他事件满足隐藏条件时，系统自动生成待领取奖励。用户不需要进入收集页寻找它。

显示顺序固定为：

1. 任务完成、XP 数字上浮和对应六维亮起，约 0.8 秒。
2. 如果升级，播放升级反馈，约 0.8 秒。
3. 如果触发普通成熟，先显示普通成熟卡。
4. 隐藏发现按照触发时间逐张显示。

奖励展示行为：

- 当前页面背景变暗。
- 卡片从画面中央出现。
- 普通卡显示“陪伴成熟”；隐藏卡显示“隐藏发现”。
- 卡片显示名称和明确的获得原因。
- 用户必须点击“收下”。
- 收下后卡片缩小并流向底部“收集”栏目。
- 收集图标和文字轻微抖动两次，并短暂出现蒂芙尼蓝脉冲。
- 动画结束后仍停留在用户原来的栏目，不自动跳转。
- 收集栏目保留未查看圆点，直到用户进入收集页并看到新卡片。

奖励触发和正式归档分成两个状态：

- 条件达成时立即写入持久化待领取记录，并通过唯一奖励键锁定该奖励，保证不会丢失或重复。
- 用户点击“收下”后写入已收集记录、点亮图鉴并移除待领取记录。

如果 App 在弹出过程中进入后台或被关闭，待领取记录继续保留，下次进入前台时重新展示。存在多张奖励时只显示一张，其余按稳定顺序排队，不允许覆盖当前卡片。

普通成熟卡收下并飞入收集后，下一个普通幼体立即成为当前伙伴；后续隐藏卡可以继续覆盖显示，但“今天”页面的伙伴数据已经完成补位。

开启系统“减少动态效果”时，卡片流动、翻转和抖动改为淡入淡出及颜色变化，功能结果保持一致。

## 卡片交互

收集页中的成熟卡片初始以小卡形式显示，约占手机页面六分之一。

- 第一次点击：卡片在当前页面上放大并显示正面。
- 第二次点击放大的卡片：卡片翻转并显示详细介绍。
- 再次点击卡片：可以在正反面之间切换。
- 点击卡片外部：关闭放大层并回到原滚动位置。

卡片背面至少包含：物种名称、类别、获得时间、获得原因、简短介绍，以及普通物种的四阶段进化记录。正式内容可以后续补充，数据字段应预留。

## 数据架构

采用“静态图鉴 + 持久化进度账本 + 持久化奖励队列”方案。

### 静态图鉴定义

`CollectibleDefinition` 不进入 SwiftData，随 App 版本提供：

- 稳定的物种 ID。
- 类型：普通或隐藏。
- 普通物种预设顺序。
- 四阶段素材或隐藏卡素材。
- 正反面文案。
- 灰色轮廓素材。
- 可选隐藏规则 ID。

### 持久化模型

`CollectionProgress`：

- 历史最高等级。
- 当前普通物种 ID。
- 当前普通形态。
- 最近处理的普通成熟节点。

历史最高等级负责判定哪些成长节点已经到达；当前普通物种和最近处理节点负责控制领取时序。到达成熟节点只创建待领取奖励，不提前切换当前普通物种。领取成功时，归档旧物种、推进最近处理节点并补上下一个幼体必须在同一次持久化保存中完成。

`OwnedCollectible`：

- 物种 ID。
- 来源类型：普通成熟或隐藏发现。
- 获得原因。
- 获得时间。
- 是否已查看。
- 唯一奖励键。

`PendingCardReward`：

- 唯一奖励键。
- 物种 ID。
- 奖励类型。
- 获得原因。
- 触发时间和稳定排序值。

唯一奖励键对普通成熟奖励使用成熟等级或物种 ID，对隐藏奖励使用规则 ID。模型层唯一约束与领域层查询共同保证幂等。

### 领域服务

- `CompanionProgressionEngine`：根据历史最高等级和静态图鉴计算当前伙伴、成长形态和普通成熟奖励。
- `HiddenAchievementEngine`：根据完成事件判断首次满足的隐藏规则。
- `CardRewardQueue`：稳定地读取和领取待奖励记录。
- `LocalDataResetService`：执行 Debug 全量重置。

视图只展示领域结果，不在 SwiftUI 点击事件中重复实现等级、成熟和隐藏条件算法。

## 状态与数据流

完成任务时：

1. 写入完成记录并增加 XP。
2. 更新当前显示等级。
3. 计算并更新历史最高等级。
4. 由普通成长引擎检查是否首次到达成熟节点。
5. 由隐藏成就引擎检查新完成事件。
6. 将新奖励以唯一键写入待领取队列。
7. 先播放现有任务和升级反馈，再由全局奖励展示层消费队首。
8. 用户点击普通成熟卡的“收下”后，在一次保存中创建已收集记录、推进当前伙伴、补上下一个幼体并删除待领取记录。
9. 用户点击隐藏卡的“收下”后，在一次保存中创建已收集记录并删除待领取记录，不改变当前伙伴。

进入收集页时，将当前已经可见的新卡片标记为已查看，并清除底部栏未查看提示。

## Debug 全量重置

“我的”页面暂时增加“重置全部本地数据”按钮，仅在 Debug 构建显示。

- 使用危险操作样式。
- 第一次点击展示影响范围。
- 第二次确认后才执行。
- 清除 XP、等级、历史最高等级、任务、完成事件、自评、状态快照、收集记录、待领取奖励、金币、奖励商品、兑换历史及本地商品图片。
- 重置后返回 Day 0、Lv.0，显示物种 1 幼体。
- Release 构建不显示入口。

项目仍处开发阶段，本阶段不为已有本地数据回填收集历史；开发者通过该入口回到统一初始状态。

## 错误与边界处理

- 找不到图鉴定义时，不崩溃；跳过无效奖励并记录可诊断信息。
- 图鉴物种不足以覆盖当前等级时，保持最后一个可用状态，不重复发放最后一张卡。
- 领取保存失败时，卡片保持在待领取队首并允许重试，不能只播放动画后丢失。
- 重复完成事件、重复进入前台或视图重建都不能重复生成奖励。
- 当前没有待领取奖励时，全局覆盖层必须完全移除，不能拦截底层点击。
- 静态图鉴排序必须稳定，避免升级 App 后已获得卡片映射到其他物种。

## 可访问性

- VoiceOver 读出卡片名称、来源、获得原因、是否已收集和当前正反面。
- 图鉴灰色轮廓不能只依赖颜色表达未解锁状态，应同时提供“尚未发现”文本或可访问性标签。
- 卡片弹层将焦点移动到卡片标题；关闭后恢复到原页面合理位置。
- 所有动画遵守“减少动态效果”。

## 验收标准

- 新用户从 Lv.0 和物种 1 幼体开始。
- 达到 Lv.1 时，物种 1 自动弹出成熟奖励；收下后归档并立即出现物种 2 幼体。
- Lv.2、Lv.3 正确显示物种 2 的第二、第三形态；Lv.4 收下物种 2 后立即出现物种 3 幼体。
- 撤销 XP 可以降低显示等级，但不会撤销、重复发放或倒退任何已触发收集进度。
- 隐藏条件达成后，无论用户在哪个栏目，奖励都会在既有反馈结束后自动出现。
- 强制关闭并重新打开 App 后，未领取奖励仍能继续展示。
- 多个奖励严格按普通成熟优先、隐藏发现随后、触发时间稳定排序。
- 收下动画结束后不自动切换栏目，收集栏目抖动并保留未查看提示。
- 进入收集页能看到成熟卡片；点击可放大，再次点击可翻面，点击外部关闭且不改变滚动位置。
- 图鉴正确区分已点亮卡片和灰色未发现轮廓，未解锁隐藏条件不会泄露。
- Debug 全量重置清除所有本地业务数据和商品图片，并恢复 Day 0、Lv.0、物种 1 幼体。
- Release 构建不显示重置入口。
- “奖励”栏目存在但只显示明确的待开发占位内容。
- iPhone 17 Pro 上四栏、卡片弹层和图鉴不存在截断、重叠或无法点击区域。
